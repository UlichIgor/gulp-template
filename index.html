Автоматизація фронтенд-розробки

Менше рутини.
Більше контролю над збіркою.

Цей шаблон допомагає автоматизувати підготовку сайту: компілює стилі та скрипти, обробляє HTML, зображення, шрифти й ресурси. Нижче — коротке пояснення кожної дії та порядок роботи.

Переглянути завданняВідкрити GitHub ↗

Що робить кожне завдання

Оберіть режим, щоб переглянути відповідні етапи збірки.

01 / CLEAN

Очищення

Видаляє попередні згенеровані файли, щоб нова збірка не змішувалася із застарілими результатами.

CleanCleanBuildОчищуються робочі папки assets або dist.
02 / FONTS

Конвертація шрифтів

Перетворює вихідні TTF-шрифти у WOFF2 — компактніший формат для швидшого завантаження у браузері.

FontsWoff2FontsWoff2BuildДжерело: src/fonts.
03 / IMAGES

Оптимізація зображень

Конвертує підтримувані JPG, JPEG та PNG у WebP, щоб зменшити вагу графіки й пришвидшити сторінки.

WebpImagesWebpImagesBuildДжерело: src/images.
04 / RESOURCES

Копіювання ресурсів

Переносить файли, які не потребують компіляції: наприклад, документи, іконки або інші статичні матеріали.

ResourcesResourcesBuildДжерело: src/resources.
05 / STYLES

Компіляція стилів

Перетворює SCSS на CSS, додає сумісні префікси та формує файл стилів. У режимі розробки створюються карти коду.

StylesStylesBuildДжерело: src/scss.
06 / SCRIPTS

Обробка JavaScript

Збирає модулі через Webpack, обробляє код Babel і готує компактний JS-файл для підключення на сторінці.

ScriptsScriptsBuildДжерело: src/js.
07 / SPRITE

SVG-спрайт

Об’єднує окремі SVG-іконки в спрайт і генерує стилі, щоб повторно використовувати графіку без зайвих запитів.

SpriteSpriteBuildДжерело: src/images/svg.
08 / HTML

Збирання HTML

Підставляє частини сторінки через include-директиви. У production-режимі додатково стискає HTML.

HtmlHtmlBuildДжерело: src/*.html та src/html.
09 / LIVE SERVER

Локальний перегляд

Запускає BrowserSync, відкриває сайт локально та оновлює сторінку після змін у файлах.

BrowsersyncДля щоденної роботи й швидкої перевірки змін.
09 / OUTPUT

Фінальна папка

Зберігає підготовлені файли у dist. Саме цю папку слід передавати на хостинг або використовувати для публікації.

distРезультат production-збірки.

Як почати роботу

Стандартний порядок підготовки локального середовища.

КРОК 01Встановіть Node.jsПотрібне середовище Node.js та npm для запуску інструментів.
КРОК 02Встановіть залежностіУ корені проєкту виконайте npm install.
КРОК 03Підготуйте файлиHTML, SCSS, JS, шрифти й зображення зберігайте у відповідних папках src.
КРОК 04Запустіть і перевіртеПісля виправлення конфігурації запустіть dev-завдання та перевірте результат у браузері.
Перед публікацією: Gulp-пайплайн виправлено: потоки й Promise повертаються коректно, production-збірка не запускає постійний BrowserSync-сервер, а SVG-спрайт генерується до компіляції SCSS. Перед деплоєм виконайте npm run prod і перевірте вміст папки dist на своєму середовищі.

Структура проєкту

Де шукати вихідні файли та результати обробки.

src/

Вихідні матеріали сайту: HTML, SCSS, JavaScript, зображення, шрифти та ресурси.

gulp/dev/

Завдання для режиму розробки та локального перегляду.

gulp/prod/

Завдання для оптимізації та підготовки файлів до публікації.

assets/ · dist/

Згенеровані файли: assets — робочий результат розробки, dist — production-результат.
