# Практичний курс Gulp для початківців

**Рівень:** початковий  
**Мова:** українська  
**Формат:** короткі уроки + практика в цьому репозиторії  
**Мета:** навчитися запускати та розуміти автоматизовану frontend-збірку, а не просто копіювати команди.

---

## Як проходити курс

1. Виконуйте уроки по порядку.
2. Після кожного уроку повторюйте команду самостійно.
3. Не редагуйте файли в `assets/` або `dist/` вручну — це результати збірки.
4. Якщо щось не працює, спочатку прочитайте повідомлення термінала, а потім розділ «Типові помилки».
5. Зберігайте свої зміни в Git невеликими логічними комітами.

## Урок 0. Підготовка робочого місця

### Що встановити

- **Node.js LTS** — середовище, у якому запускається JavaScript поза браузером.
- **npm** — менеджер пакетів, який встановлює бібліотеки та запускає команди проєкту.
- **Git** — система контролю версій.
- **Редактор коду** — наприклад, Visual Studio Code.

Завантаження: [Node.js](https://nodejs.org/), [Git](https://git-scm.com/), [Visual Studio Code](https://code.visualstudio.com/).

### Перевірка

Відкрийте термінал і виконайте:

```bash
node --version
npm --version
git --version
```

Якщо кожна команда показує номер версії, інструмент доступний.

### Завантаження навчального проєкту

```bash
git clone https://github.com/UlichIgor/gulp-template.git
cd gulp-template
npm ci
```

**Що означають команди:**
- `git clone` завантажує репозиторій на комп'ютер.
- `cd` переходить у папку проєкту.
- `npm ci` встановлює точні версії пакетів із `package-lock.json`.

**Практика:** перевірте, що в корені є `package.json`, `package-lock.json`, `src/` і `gulp/`.

## Урок 1. Що таке Gulp

Gulp — інструмент автоматизації. Він запускає задачі, які обробляють файли: компілюють SCSS, об'єднують HTML-фрагменти, збирають JavaScript, копіюють ресурси та готують оптимізовану версію сайту.

Основні поняття:

- **Task (задача)** — функція, яка виконує одну операцію.
- **Stream (потік)** — послідовність файлів, що проходить через кроки обробки.
- **src()** — знаходить вхідні файли.
- **pipe()** — передає файли наступному кроку.
- **dest()** — записує результат у папку.
- **series()** — запускає задачі послідовно.
- **parallel()** — запускає незалежні задачі паралельно.

Спрощений приклад:

```js
const { src, dest } = require("gulp");

function copyFiles() {
  return src("src/resources/**/*")
    .pipe(dest("assets"));
}

module.exports = { copyFiles };
```

Функція повертає потік. Це важливо: Gulp має знати, коли задача справді завершилася.

**Практика:** знайдіть у `gulp/dev/Resources.js` виклики `src()`, `pipe()` та `dest()`.

## Урок 2. Структура проєкту

Усі файли, які ви редагуєте, зберігаються у `src/`. Папки `assets/` і `dist/` створюються автоматично.

| Шлях | Призначення |
| --- | --- |
| `src/index.html` | Головний HTML-документ |
| `src/html/` | Частини HTML-сторінки |
| `src/scss/` | Стилі SCSS |
| `src/js/` | JavaScript |
| `src/images/` | Зображення та SVG |
| `src/fonts/` | TTF-шрифти |
| `src/resources/` | Статичні файли |
| `gulp/dev/` | Задачі для розробки |
| `gulp/prod/` | Задачі для production |

Файл `paths.js` містить шляхи до джерел і папок призначення. Якщо змінюєте структуру папок, перевіряйте відповідні шляхи там.

**Практика:** відкрийте `paths.js` і знайдіть, звідки беруться SCSS-файли та куди записується CSS.

## Урок 3. HTML і повторне використання фрагментів

Головна сторінка знаходиться в `src/index.html`. У ній підключені окремі фрагменти:

```html
@@include('./html/header.html')
@@include('./html/content.html')
@@include('./html/footer.html')
```

Під час збірки `gulp-file-include` вставляє вміст фрагментів у сторінку. Це зручно: шапку й підвал можна змінити в одному файлі, а не дублювати в багатьох HTML-документах.

У задачі `Html` формується HTML для розробки. У `HtmlBuild` додатково стискається розмітка.

**Практика:**
1. Відкрийте `src/html/content.html`.
2. Змініть текст заголовка.
3. Запустіть `npm run dev`.
4. Переконайтеся, що зміни з'явилися у браузері.

## Урок 4. SCSS і CSS

SCSS — розширений синтаксис CSS. Він підтримує змінні, вкладені правила, міксини та поділ стилів на модулі.

Головний файл стилів — `src/scss/main.scss`. Він підключає інші файли. Наприклад:

```scss
$brand-color: #2457a6;

.button {
  background: $brand-color;
  color: #fff;

  &:hover {
    opacity: 0.85;
  }
}
```

Задача Styles:
1. читає SCSS;
2. компілює його в CSS за допомогою Sass;
3. додає сумісні браузерні префікси через Autoprefixer;
4. записує CSS у `assets/css/`;
5. створює source map, щоб у DevTools можна було знайти вихідний SCSS.

Production-задача створює оптимізований CSS у `dist/css/`.

**Практика:** змініть колір у файлі `src/scss/page/_content.scss` або додайте власне правило до відповідного модуля стилів. Перевірте результат.

## Урок 5. JavaScript, Webpack і Babel

Вхідний JavaScript розміщується в `src/js/`. Webpack збирає модулі в один файл, а Babel допомагає перетворити сучасний JavaScript для ширшої сумісності з браузерами.

Приклад для `src/js/main.js`:

```js
"use strict";

document.addEventListener("DOMContentLoaded", () => {
  console.log("Навчальний проєкт Gulp запущено!");
});
```

Задача Scripts формує файл `scripts.min.js` у `assets/js/`. Production-варіант використовує режим Webpack `production` та створює файл у `dist/js/`.

**Практика:** додайте приклад вище, перезапустіть збірку й перевірте повідомлення в консолі браузера (DevTools → Console).

## Урок 6. Зображення, шрифти та статичні ресурси

У проєкті є окремі задачі:

- **WebpImages** — перетворює JPG/JPEG/PNG на WebP.
- **FontsWoff2** — конвертує TTF у WOFF2.
- **Resources** — копіює favicon та інші статичні файли.
- **Sprite** — формує SVG-спрайт з іконок у `src/images/svg/`.

Формати WebP та WOFF2 зазвичай допомагають зменшити обсяг файлів, які завантажує браузер. Не видаляйте оригінали, поки не перевірили результат.

**Практика:** додайте тестове JPG-зображення до `src/images/`, запустіть `npm run prod` і перевірте, чи з'явився WebP у `dist/images/`. Додайте SVG-іконку до `src/images/svg/` і перевірте створений спрайт.

## Урок 7. Режим розробки та BrowserSync

Запустіть:

```bash
npm run dev
```

Команда виконує послідовність підготовки, потім запускає BrowserSync. Він створює локальний сервер і стежить за змінами HTML, SCSS та JavaScript. Після завершення відповідної задачі браузер оновлюється.

Зупинка: `Ctrl + C` у терміналі.

Якщо сторінка не відкрилася автоматично, подивіться адресу локального сервера в терміналі.

**Практика:** змініть текст у HTML, збережіть файл і спостерігайте за оновленням браузера без ручного перезавантаження.

## Урок 8. Production-збірка та публікація

Коли сайт готовий, створіть production-версію:

```bash
npm run prod
```

У результаті формується папка `dist/`. Вона містить HTML, CSS, JavaScript, шрифти, зображення та інші ресурси, потрібні для розміщення сайту.

Перед публікацією перевірте:
- чи є `dist/index.html`;
- чи завантажуються CSS та JavaScript;
- чи правильні шляхи до зображень, шрифтів та favicon;
- чи немає помилок у консолі браузера.

Публікація через gh-pages:

```bash
npm run deploy
```

Команда завантажує вміст `dist/` у гілку, яку використовує GitHub Pages. Запускайте її лише після успішної перевірки production-збірки.

**Практика:** зберіть сайт командою `npm run prod`, перевірте папку `dist/`, а тоді опублікуйте його, якщо маєте налаштований GitHub Pages.

## Фінальний проєкт

Створіть невелику односторінкову сторінку на власну тему (портфоліо, кав'ярня, майстерня або сторінка послуги).

Обов'язкові умови:
1. Є шапка, основний контент і підвал, винесені в HTML-фрагменти.
2. Стилі організовані через SCSS.
3. Є хоча б одна взаємодія на JavaScript.
4. Підключено favicon і хоча б одне зображення.
5. Сторінка коректно працює після `npm run dev`.
6. Production-версія створюється через `npm run prod`.

## Самоперевірка

Спробуйте відповісти без підказок:

1. Чим відрізняються `src()` і `dest()`?
2. Для чого Gulp потрібне повернення потоку із задачі?
3. Чим відрізняються `series()` і `parallel()`?
4. Де потрібно редагувати стилі: у `src/` чи у `dist/`?
5. Для чого використовують BrowserSync?
6. Чому production-збірку потрібно перевіряти перед публікацією?

**Відповіді для самоперевірки:** `src()` читає вхідні файли, `dest()` записує результат; повернений потік дозволяє Gulp відстежити завершення задачі; `series()` виконує послідовно, `parallel()` — одночасно; редагують файли у `src/`; BrowserSync дає локальний сервер і оновлення браузера; перевірка виявляє відсутні файли, неправильні шляхи та помилки до деплою.

## Типові помилки

| Симптом | Що перевірити |
| --- | --- |
| `node` або `npm` не знайдено | Перевстановіть Node.js LTS і відкрийте новий термінал |
| `npm ci` завершується помилкою | Переконайтеся, що ви в корені проєкту й не видалили lock-файл |
| Gulp не знаходить файли | Перевірте шлях і назву файлу в `paths.js` |
| Зміни не видно в браузері | Перевірте термінал, помилки збірки й адресу BrowserSync |
| У `dist/` немає ресурсу | Перевірте, чи є вихідний файл у `src/` та чи підходить його розширення до glob-шаблону |
| Сторінка не має стилів | Перевірте шлях до CSS у HTML і наявність файлу в `dist/css/` |
