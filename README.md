# Gulp Template

Набір Gulp-завдань для автоматизації фронтенд-розробки: компіляція SCSS, обробка JavaScript, збирання HTML, оптимізація зображень, конвертація шрифтів і копіювання статичних ресурсів.

> **Стан проєкту:** документацію та публічну довідкову сторінку оновлено. Перед використанням команд збірки потрібно завершити технічне виправлення Gulp-тасків: у поточній реалізації виявлено некоректне завершення callback/потоків, а функції `development` і `production` мають помилковий спосіб запуску. Не використовуйте production-деплой до усунення цих проблем і успішного тестового build.

## 1. Вимоги

- Node.js та npm.
- Git для отримання й оновлення проєкту.
- Встановлені залежності з `package.json`.

Проєкт декларує Node.js `>=18`. Рекомендовано використовувати актуальну LTS-версію Node.js.

## 2. Встановлення

У корені репозиторію виконайте:

```bash
npm install
```

Команда встановлює Gulp, компілятори, оптимізатори та інші інструменти, перелічені в `package.json`.

## 3. Команди проєкту

| Команда | Призначення |
| --- | --- |
| `npm run dev` | Запуск dev-збірки та локального BrowserSync-сервера |
| `npm run prod` | Створення оптимізованої збірки у `dist` |
| `npm run clean` | Очищення згенерованих папок, перелічених у скрипті clean |
| `npm run deploy` | Публікація вмісту папки dist через gh-pages; запускати лише після успішного production build |

## 4. Що роблять завдання

### Підготовка файлів

- **Clean / CleanBuild** — очищення попередніх згенерованих файлів перед новою збіркою. Clean працює з папкою `assets`, CleanBuild — з `dist`.
- **FontsWoff2 / FontsWoff2Build** — конвертація TTF-шрифтів у WOFF2 для зменшення розміру шрифтів, що завантажуються браузером.
- **WebpImages / WebpImagesBuild** — конвертація JPG/JPEG/PNG-зображень у WebP.
- **Resources / ResourcesBuild** — копіювання статичних файлів із `src/resources` у вихідну папку.

### Обробка інтерфейсу

- **Styles / StylesBuild** — компіляція SCSS у CSS та додавання браузерних префіксів; dev-режим створює source maps.
- **Scripts / ScriptsBuild** — збирання JavaScript через Webpack і Babel та мінімізація підготовленого коду.
- **Sprite / SpriteBuild** — створення SVG-спрайту зі значків, розміщених у `src/images/svg`.
- **Html / HtmlBuild** — об'єднання HTML-фрагментів через `gulp-file-include`; production-варіант також стискає HTML.

### Перегляд у браузері

- **Browsersync** — локальний сервер для розробки та автоматичне оновлення сторінки після змін у вихідних файлах.
- У production-режимі BrowserSync не запускається, тому команда збірки завершується й може використовуватися перед деплоєм.

## 5. Структура каталогів

```text
src/
  html/       HTML-фрагменти сторінки
  images/     вихідні зображення та SVG-іконки
  fonts/      TTF-шрифти
  js/         JavaScript-файли
  resources/  статичні ресурси
  scss/       SCSS-стилі

gulp/
  dev/        завдання для розробки
  prod/       завдання для production

assets/       згенеровані файли для локальної розробки
dist/         production-результат
```

## 6. Рекомендований порядок роботи

1. Додайте вихідні матеріали у відповідні папки `src`.
2. Встановіть залежності через `npm install`.
3. Переконайтеся, що Gulp-конфігурація та всі таски проходять перевірку.
4. Запустіть режим розробки та перевірте сторінку в браузері.
5. Виправте помилки й сформуйте production-збірку.
6. Перевірте вміст `dist` локально.
7. Лише після успішної перевірки виконайте публікацію.

## 7. Важливі технічні зауваження

Перед відновленням повноцінного автоматичного build потрібно:

- виправити `development` та `production` у `gulpfile.babel.js`, щоб вони повертали коректно сформовані Gulp-композиції, а не викликали самі себе;
- у кожному таску повертати Gulp stream або використовувати callback — не завершувати callback синхронно до завершення потоку;
- прибрати BrowserSync із фінального production build або винести його в окрему команду попереднього перегляду;
- узгодити шляхи `assets`, `dist` та команду `clean`;
- перевірити збірку на актуальній LTS-версії Node.js.
